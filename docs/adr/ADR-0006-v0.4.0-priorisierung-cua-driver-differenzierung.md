**Status:** Proposed

## Context

ADR-0005 identifizierte Snapshot/Element-ID als nächstes architektonisches Hebelmittel
und klassifizierte 37 Capabilities in A/B/C-Prioritäten. Seitdem wurde der cua-driver
0.6.5 (Hermes-intern, trycua-basiert) live getestet und verglichen.

### cua-driver Vergleichsevidenz (live getestet, 2026-06-24)

cua-driver ersetzt peekxd **nur** für den engen Use Case "Hermes-Agent macht
Screenshot+Klick auf X11". Es fehlen: Wayland, Safety-Familie, Snapshot/Element-ID,
MCP-Server, Audit-Trail, autonome Loop, Vision find_element, WSLg, Multi-Agent-Support.

**Strategische Schlussfolgerung:** peekxd ist kein Hermes-Ersatz, sondern ein
unabhängiges Linux-Automation-Tool mit drei Differenzierungsmerkmalen:
1. Safety-Familie (Ghost/Shadow/Zones/Audit-Trail)
2. Wayland/WSLg (einzige Cross-Display-Server-Lösung auf Linux)
3. Snapshot/Element-ID (v0.4.0 — das architektonische Hebelmittel)

---

## Decision

ADR-0005's A-Prioritäten werden bestätigt und mit cua-driver-Vergleich neu priorisiert.
v0.4.0 hat **drei Epics** mit klarer Reihenfolge.

### Epic 1: Safety-Moat MCP-Exposition (PRIORITÄT A — parallel zu Epic 2)

Die Softbox-Familie ist peekxd's stärkster Moat — kein Konkurrent hat klassifizierte,
blockierbare, auditierte Desktop-Aktionen auf Linux. Aktuell ist sie NUR im CLI
(`peekxd agent run --ghost`) und intern verfügbar, aber NICHT im MCP-Server.

**Gap:** `peekxd/mcp_server.py` hat 0 Safety-Integration. Externe MCP-Clients
(Claude Code, Codex, etc.) haben keinen Zugang zu Ghost/Shadow/Zones/Audit.

**MCP-Server-Erweiterung:**
- Jede bestehende MCP-Tool-Aktion (click, type, key, scroll, drag) MUSS durch
  die SafetyGuard-Pipeline gehen
- Neue MCP-Tools:
  - `peekxd_set_safety_level` → `{level: strict|normal|permissive}`
  - `peekxd_ghost_preview` → `{action, params}` → returns GhostPreviewResult ohne Ausführung
  - `peekxd_audit_export` → `{session_id}` → returns Audit-Trail als JSON
  - `peekxd_zone_check` → `{action, params}` → returns Zone (GHOST/SHADOW/GUIDED/DIRECT)
- Jede Aktion gibt `zone` und `audit_id` im Response zurück

**Architektur:**
- `SafetyMiddleware` im MCP-Server: intercept vor jeder Action-Execution
- SafetyGuard wird stateful pro MCP-Session (Level persistiert)
- Audit-Trail aktiviert by default für MCP-Clients

**Tests (Minimum):**
- MCP click ohne Safety → funktioniert (backward compat)
- MCP click mit SafetyLevel STRICT → GHOST preview, keine Ausführung
- MCP ghost_preview auf `rm -rf /` → HARD_BLOCKED
- MCP audit_export liefert vollständigen Trail
- Safety-State persistiert innerhalb einer MCP-Session

**Acceptance Criteria:**
- Claude Code über MCP bekommt Ghost/Shadow/Audit-Schutz
- `peekxd_set_safety_level` ändert Verhalten für nachfolgende Calls
- Audit-Trail für jede MCP-Aktion schreibbar
- Keine Regression in bestehenden MCP-Tools

### Epic 2: Snapshot/Element-ID Core (PRIORITÄT A — höchste)

Das architektonische Hebelmittel. Ohne dies ist peekxd "ein weiterer
koordinatenbasierter Klicker" und cua-driver ist "good enough".

**Backend:**
- `SnapshotStore` — In-Memory + Disk-Cache mit TTL
  - Format: `{snapshot_id, timestamp, screen_image_path, elements: [...]}`
  - Snapshot-ID-Format: `SNAP-YYYYMMDD-NNN`
  - TTL default: 24h, konfigurierbar via `peekxd snapshot clean --older-than H`
- `ElementDetector` — hybride Element-Erkennung (AT-SPI2 + Vision)
  - Element-ID-Format: `E<seq>` (z.B. `E1`, `E2`, `B1` für Buttons, `T1` für Text)
  - Stabilität: Position + Role + Label Hash für reproduzierbare IDs
  - Fallback: AT-SPI2 Baum wenn Vision nicht verfügbar

**CLI:**
- `peekxd see --json` → returns `{snapshot_id, elements: [...]}`
- `peekxd click --on <element_id> --snapshot <snapshot_id>`
- `peekxd type --on <element_id> --text <text> --snapshot <snapshot_id>`
- `peekxd inspect --snapshot <snapshot_id>` → list all elements
- `peekxd snapshot list` → active snapshots
- `peekxd snapshot clean --older-than <hours>`

**MCP:**
- `peekxd_see` → `{snapshot_id, elements}`
- `peekxd_click_on` → `{element_id, snapshot_id, button}`
- `peekxd_type_on` → `{element_id, snapshot_id, text}`
- `peekxd_inspect_snapshot` → `{snapshot_id}`
- `peekxd_snapshot_list`, `peekxd_snapshot_clean`

**Tests (Minimum):**
- Snapshot creation + retrieval
- Element-ID stability across re-captures
- Click by element_id resolves correct coordinates
- Snapshot TTL expiry
- see --json returns valid schema

**Acceptance Criteria:**
- `peekxd see --json` returns snapshot_id + ≥1 element on a real desktop
- `peekxd click --on E1 --snapshot SNAP-...` clicks the correct element
- Coordinates from cached snapshot match live position within 5px
- Snapshot cache does not grow unbounded (TTL enforced)

### Epic 3: AT-SPI2 Action-First (PRIORITÄT B — nach Epic 2)

Reduziert synthetische Input-Fehler. Statt Koordinaten-Klick → direkte
Accessibility-Action.

**CLI:**
- `peekxd set-value --on <element_id> --value <value> --snapshot <snap>`
- `peekxd perform-action --on <element_id> --action <action> --snapshot <snap>`

**Backend:**
- AT-SPI2 `set_value()` für text fields, sliders, checkboxes
- AT-SPI2 `do_action()` für buttons (action name mapping: `press`, `click`, `activate`)
- Fallback auf synthetischen Input wenn AT-SPI2 nicht verfügbar

**Tests:**
- set-value on a text field changes the actual value
- perform-action on a button triggers activation
- Graceful fallback when AT-SPI2 action unavailable

### Epic 4: Wayland Hardening + WSLg Stabilisierung (PRIORITÄT B — parallel)

cua-driver ist X11-only. Wayland-Support ist ein Alleinstellungsmerkmal.

**Wayland:**
- `grim` + `slurp` für Screenshot/Region-Capture
- `wtype` + `ydotool` für Input (ydotool braucht ydotoold Daemon)
- AT-SPI2 funktioniert auf Wayland gleich (Session-Bus statt X11)
- Fix: Socket-Path UID-Bias (Cycle 15 Finding 3)

**WSLg:**
- Bestehender Fallback stabilisieren
- HiDPI-Scaling validieren

**Tests:**
- Wayland capture returns valid image (requires Wayland session)
- WSLg capture returns valid image (requires WSL environment)
- Input injection works on Wayland (wtype/ydotool)

## Non-Goals

- **Kein Peekaboo-Clone.** Adoptiere Konzepte, nicht Swift-Implementierung.
- **Keine macOS-Features.** Dock, Spaces, Menu Bar, TCC sind out of scope.
- **Kein cua-driver-Paritäts-Kandidat.** "Screenshot+Klick auf X11" ist cua-driver's Job.
- **Kein Browser-Tool.** Playwright/Selenium MCP bridge ist separater Epic (v0.5.x).
- **Kein Daemon.** Background process für warm screenshots ist v0.5.x.

## Guardrails

- Keine Breaking Changes für bestehende CLI-Befehle (`click X Y` bleibt funktionieren)
- Snapshot-Cache Größe limitiert (default max 500 MB)
- Element-IDs müssen deterministisch sein (selbe Elemente → selbe IDs bei Re-Capture)
- Wayland-Code path darf X11 nicht brechen
- MCP-Tool-Namespace bleibt `peekxd_*`

---

## Acceptance Criteria (v0.4.0 Release)

1. `peekxd see --json` funktioniert auf X11 und liefert snapshot_id + elements
2. `peekxd click --on E1 --snapshot SNAP-...` klickt das richtige Element
3. Snapshot-Cache respektiert TTL und Größenlimits
4. AT-SPI2 `set-value` funktioniert für mindestens text_field und checkbox
5. Wayland-Capture funktioniert (getestet auf TUXEDO OS Wayland-Session)
6. MCP-Server bietet alle 6 neuen Tools
7. Alle neuen Features haben Tests
8. Keine Regression in bestehenden 451 Tests
